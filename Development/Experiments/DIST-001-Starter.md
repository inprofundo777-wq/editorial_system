## Рабочая инструкция

Все результаты последовательно добавляются ниже в этот же документ.

Не создавать заранее пустые секции под:

- Reader;
- SEO;
- Strategy;
- Telegram;
- Facebook;
- Microformats;
- Visual;
- другие роли.

Порядок и обязательность аналитических ролей проверяются практикой.

Когда активный Editor завершил работу, Owner:

```text
1. получает цельный Markdown-результат;
2. вставляет его в конец этого документа;
3. меняет статус текущего шага: 0 → +;
4. меняет статус следующего шага: - → 0;
5. передаёт следующему Editor ту же ссылку.
```

Каждый Editor должен:

1. физически открыть актуальную версию `DIST-001`;
2. проверить Process Map;
3. работать только с активным шагом `0`;
4. использовать Source article и уже добавленные результаты;
5. вернуть один цельный Markdown-блок;
6. не повторять шапку и структуру всего документа;
7. не создавать параллельный рабочий документ;
8. не изменять решения Portfolio или опубликованный Source;
9. отмечать обнаруженное новое знание по уровню маршрутизации.

## Output Contract активного шага

Первый активный Editor должен вернуть:

```markdown
# [Название фактически выполненного шага]

## Роль результата

Кратко: какую Distribution-задачу решает результат.

## Анализ

Только выводы, необходимые для последующего Distribution.

## Рекомендованный следующий шаг

- какой Editor или функция нужны дальше;
- почему этот шаг необходим;
- какой результат от него ожидается.

## Feedback Signals

### Editor-level

- только если обнаружено.

### Content-intelligence

- только если обнаружено новое знание уровня корпуса.

### System-level

- только если обнаружен процессный или архитектурный сигнал.
```

Этот Output Contract является стартовым условием EXP-002, а не постоянным стандартом.

## Ограничения

Внутри DIST-001 не следует:

- заново выбирать тему;
- переписывать опубликованную статью;
- открывать Formation;
- пересматривать Portfolio;
- заранее объявлять Reader, SEO или Strategy обязательными;
- создавать новую постоянную роль;
- проектировать Distribution System;
- создавать отдельные документы для каждого Editor;
- возвращать тексты каналов в Notion.
