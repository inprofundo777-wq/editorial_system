# Publication Master — Workflow

## Паспорт

| Поле | Значение |
|---|---|
| Статус | v0.1 Candidate / Awaiting Validation |
| Функция | последовательность одного Publication Master assignment |

## 1. Intake

1. Прочитать Activation и Canonical entry.
2. Восстановить Role Charter и применимые источники.
3. Проверить Process Authority Envelope.
4. Назвать основную и временную роль, если она включается.

## 2. Qualification

1. Сформулировать material signal.
2. Проверить существующую capability.
3. Классифицировать уровень: Local / Role / System / Structural-Authority.
4. Вернуть local work естественному owner.
5. Остановиться перед неразрешённым structural change.

## 3. Work

В зависимости от assignment:

- провести diagnosis;
- собрать evidence;
- сравнить варианты;
- подготовить минимальный experiment;
- разработать Change Set;
- выполнить разрешённую системную или интеграционную проверку;
- временно войти в Coach capability по отдельному контракту.

Во время работы не переоткрывать утверждённые upstream decisions без material deviation.

## 4. Result

Результат содержит:

- Decision / finding;
- evidence и ограничения;
- Capability Delta, если выявлен gap;
- Improvement Package или Owner Decision, если требуется;
- allowed record;
- следующий owner и authorized step.

## 5. Record

Если запись разрешена:

1. перечитать target и immediate dependencies;
2. выполнить только названную операцию;
3. перечитать записанный результат;
4. проверить status, version, links и semantic consistency;
5. сохранить material provenance.

## 6. Handoff and Exit

Передать один цельный блок. Затем явно:

- вернуть ownership Coach, профильной роли, Owner или Project Overview;
- завершить временную capability;
- назвать later validation;
- прекратить operating control над переданной областью.

## 7. Development loop

```text
Practice
→ Finding
→ Pattern check
→ Development candidate
→ Owner ADOPT / TEST / DEFER
→ Documentation Update
→ Validation
```

Finding не становится постоянным правилом напрямую.
